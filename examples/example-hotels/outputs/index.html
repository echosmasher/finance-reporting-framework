Example Hotels

Live demo — finance-reporting-framework

Four fictional Nordic properties, three months of synthetic data. Four stories were planted in the numbers below — read them here, then open the real, committed dashboard each one produced. See the repo for how this was built, or this demo's README for the exact numbers and how to verify them from the committed CSVs yourself.

The guided tour

1

February: Utilities came in 20% under Budget at Example Hotel Oslo. Looks like a win.

It isn't. The electricity invoice never arrived that month — only a token 5,267 NOK "estimated accrual" posted, while every other utilities account (heating, water, waste, fuel) sat at its normal level. March shows the real story: usage catches up, plus the unpaid February charge, for a +34.3% overshoot. The framework flagged both months, and the transaction drill-down on each makes the cause obvious without anyone digging through a GL export by hand.

See the February "win" → See March catch up →
2

One transaction moved a whole month's F&B cost line 40% over Budget.

At Example Hotel Bergen, a single 203,321 NOK inventory write-off — "obsolete and spoiled stock following physical count" — landed the entire month's F&B Cost of Sales variance in one entry. Every other F&B account was normal. The drill-down isolates it instantly. This dashboard also carries real reviewer edits made via /feedback after the fact: a comment from the F&B manager confirming the write-off was a scheduled count, not a control issue, and a redundant narrative note suppressed.

See the flagged dashboard →
3

Occupancy was flat. Payroll wasn't.

Example Hotel Copenhagen's Rooms Payroll ran 25% over Budget in March while occupancy moved less than a point (rooms sold −2.3% vs. Budget — essentially on target). Overtime and a temporary staffing agency, not guest demand, explain the gap — exactly the payroll-diverging-from-occupancy signal the framework's investigation guide is built to catch, surfaced automatically instead of buried in a 150-account GL export.

See the March dashboard →
4

Three months, zero manufactured problems.

Example Hotel Stockholm beats Budget on Gross Operating Profit every single month (+1.6% / +2.6% / +0.5%), with nothing outside expected seasonality ever flagged. The point isn't that nothing ever goes wrong at Stockholm — it's that the framework doesn't invent a story when there isn't one. A tool that only ever finds problems isn't trustworthy; this one knows when to say nothing.

See a clean quarter →

All four entities also show a real, deliberate January seasonality spike (an annual insurance premium and audit fee, invoiced as one lump sum) that the framework flags mechanically every January and the narrative then explains as expected — not one of the four headline stories above, but a live exercise of the same "flag first, explain second" mechanism. See the demo README's seasonality section for the details.
